# Whole-codebase review, 2026-10-04 (branch feat/department-journeys, at 735c6b0)

Five read-only reviews, one per part. Findings are from reading code; items marked (checked) I re-read myself, items marked (reported) are the reviewer's claim only.
Nothing here has been fixed yet. Order inside each part is by severity.

## Part 1. Identity, consent, department API, security

- HIGH (checked) Readiness returns other departments' person IDs. `DepartmentJourneyController.readiness` returns `DepartmentLinkNeed` including `localIdType` and `localIdToken` to the calling department. Return only department, name, categories, linked, departmentLoginAvailable.
- HIGH (checked) `LocalIdOtpLinkProofProvider` (demo code 000000) is a plain `@Component`, always on. If the optional citizen realm is ever configured, any citizen token can link any person ID. Gate it with a dev/demo profile.
- MEDIUM (reported) Citizen merge re-points links but not discovery pointers, so the survivor gets NO_POINTER for the moved department.
- MEDIUM (reported) Only create, merge and grant are audited; plain link creation, readiness, and failed assertions by an authenticated department are not.
- MEDIUM (reported) The retention purge will fail on an FK violation once a department-granted consent ages out: `consent_evidence` (V206) is never deleted.
- MEDIUM (reported) No department-side revoke: citizens who consented on a department portal cannot withdraw.
- MEDIUM (reported) `POST /api/journeys/{code}/start` checks only that the department runs the journey, not that the citizen is linked to it. The legacy `POST /api/consent/requests` lets a DEPARTMENT token create requests for any citizen.
- MEDIUM (reported) Citizen grant path is not idempotent (no PENDING check or lock): double submit gives duplicate ACTIVE artifacts.
- MEDIUM (reported) Network calls (JWKS fetch) happen inside DB transactions in `CitizenResolver`.
- MEDIUM (reported) JWKS fetching accepts http in production, host check ignores scheme/port, IPv6 ULA and CGNAT not treated as private, DNS rebinding.
- MEDIUM (reported) No unique index on active `(citizen_id, department_code)`; a REVOKED link blocks the person forever; `link()` can report success without linking the proven person; merge races.
- LOW: statement not bound to wording hash, loose `iat`/`nbf` checks on assertions, unbounded text and jti lengths cause 500s, SUSPENDED citizen only checked in `link()`, legacy return-prefix is a string prefix, `confirm` can run twice.
- Tests: `DepartmentIdentityIT` mocks the verifier, no concurrency tests, no purge-with-evidence test.

## Part 2. Catalog, onboarding, connector, orchestration, tracking, ops

- HIGH (reported, partly run) Manifest endpoint paths are not validated: a path such as `.evil.com/x` or `@169.254.169.254/` retargets the call to another host with the credentials attached.
- HIGH (reported) Any adapter exception (timeout, 4xx/5xx, bad JSON, mapping NPE) after `start` leaves an orphan application and a retry marks it VERIFIED with nothing checked, so it can then be approved.
- HIGH (reported) Terminal states (REJECTED, CLOSED) can be overwritten by a late retry or a slow start.
- HIGH (reported) A manifest can overwrite an existing department's identity spec; signed manifest does not bind the host (replay from another host within 10 minutes).
- HIGH (reported, run in jshell) SSRF guard gaps: `[::1]` passes, only first resolved address checked, discovery fetch allows http and has no size cap.
- V211 `onboarded` gaps (reported): no backfill (the live AWS DB has nothing onboarded, so no impact there); an existing source that was skipped is not flagged so its connector is dropped from the overview; highest version shown even if DRAFT while v1 still serves; UNKNOWN health counts as working; a seeded connector can satisfy an onboarded journey's `ready`; a manifest can adopt another department's journey code.
- MEDIUM: trial endpoint reads real data without consent (audit subject "sample"); `SlaBreached` never published; `slaHours` 0 makes every application born breached; notifications are only delivered for mandatory consent events; a missing record can become a success (SFTP `UNKNOWN`, JDBC `{}`); `lookup` transform is identity; retry is outermost so an open breaker still stalls ~1s; no double-start guard, DRAFT journeys can be started, fan-out is serial; `CatalogController` trusts a client-supplied `passed` flag on publish; `IssuedDocumentsImpl` returns mock fixture data; bank review is not wired to the application.
- LOW: N+1 queries, in-memory counters lost on restart, unbounded maps, OAuth token cache not invalidated on 401.
- Tests: `JourneyServiceStubEngineTest` tests a stub, `OpsOverviewIT` asserts UNKNOWN means working, no SSRF or adapter-exception tests.

## Part 3. Department services and kit

- HIGH (reported; Spring path matching verified, Tomcat end-to-end not) Auth filters decide on the raw `getRequestURI().startsWith("/v1/")`, so `/v1;x=1/...` may skip the API-key / bearer / IP / manifest-signature checks in revenue, dbt, education. Match on the normalised path or reject any `;` and protect by default.
- HIGH (known demo shortcut, deployed) One-time code is the constant 123456; no lockout, throttle or attempt cap on sign-in or verify.
- MEDIUM: sign-in unthrottled, un-pooled DB connection per attempt, timing leaks which mobiles exist; sessions and tickets cannot be revoked or used once and the cookie MAC does not include the department code; DBT uses one secret in both directions; `*-change-me` defaults fail open; key/secret files are written then chmod'ed (race) and loaded in several places.
- LOW: cookie Secure only if publicBaseUrl is https, no security headers or `no-store` on login pages; `SamanvayClient` holds a lock during the token call, logs citizen IDs in URLs, does not evict the token on 401, `PortalProperties.toString` prints secrets; consent signer signs literal "null"; Education SOAP XML not escaped; `agriculture/db/init.sql` lacks `date_of_birth`/`citizen_login` (local path only).
- Tests: no `;` bypass test, no ticket reuse or lockout test; four copy-pasted test classes.

## Part 4. Front ends

No critical findings. No `dangerouslySetInnerHTML`, open redirect or `window.open`; role gating matches the backend; every staffApi path is a live route.
- HIGH 360 degree citizen view loads the newest 200 applications and 200 audit entries then filters in the browser, so an older citizen can show "no activity". `GET /api/applications` already takes `citizenId`; audit needs a subject filter.
- MEDIUM Approve and Reject (which triggers disbursement) are one click with no confirm and stay enabled while reloading.
- MEDIUM "Completed" and "Failed" counts are really Approved and Rejected (a real FAILED or CLOSED is counted nowhere). Mislabel was not caught because the test used `arrayContaining`.
- MEDIUM `StatusStepper` shows CLOSED as "Approved"; FAILED as plain in progress.
- MEDIUM UNKNOWN (never probed) sources show "All sources working"; a DRAFT with a RED source can show "Ready to publish".
- MEDIUM No CSP header; the whole OIDC user object including the refresh token sits in sessionStorage; production sourcemaps on.
- LOW Dead citizen-era code (`i18n/*`, `auth/realm.ts`, unused staffApi list functions and types); Departments page shows the title twice ("Bank account Bank account"); portal `?linked=` banner is cosmetic; `ExceptionsPage` shows "Running" for every instance because of a backend `state()` bug; accessibility gaps.

## Part 5. Deployment, scripts, docs, tests

- HIGH Base `application.yml` defaults to `samanvay_app_dev_password` and `samanvay_migrate`/`samanvay_migrate` with no startup refusal.
- HIGH Mock departments (`mock.samanvay.test`) with fabricated data are seeded PUBLISHED and GREEN in every database (V21-V23) and `MockDepartmentBackend` is not profile-gated; the runbook calls these rows harmless.
- HIGH The public demo uses documented passwords and fixed OTP 000000 with in-memory Keycloak, and the `demo` profile enables `DemoAuditTamper` and chaos endpoints. Whoever signs in first owns admin.
- HIGH "App never holds the migrate credential" is untrue: Flyway runs in-process with it. Run Flyway as a separate job or soften the claim.
- MEDIUM CI builds only the root project: the `departments/` reactor, `DepartmentsEndToEndIT` (skipped via `assumeTrue`), the python test and the portal build never run. Department containers get the Postgres superuser password via `env_file`. Agriculture JDBC crosses the internet without TLS. Docs still point at the removed Catalog page; FINAL-CHANGES.md is stale. The middle-layer deploy (Caddy, Keycloak hostname, systemd) is not reproducible from the repo. `ArchitectureTest.modules_only_touch_their_own_tables` selects classes with no `@Table` and so checks nothing.
- LOW Missing indexes (`identity_link.citizen_id`, `consent_access_grant.consent_id`, `consent_request.subject_citizen_id`); unpinned images, root containers, DB ports bound on all interfaces; `--rotate` cannot take effect on existing volumes; `Thread.sleep` in 25 ITs.
- No real secrets found in git history or tracked files.

## Suggested fix order

1. Department `;` path bypass and readiness ID leak (small, contained).
2. Journey start robustness: catch adapter exceptions, seed step rows, only VERIFIED when all required categories COMPLETED, block terminal-state overwrite, require linked citizen on start.
3. Manifest endpoint path validation, SSRF guard gaps, host bound into the signed manifest.
4. Purge FK (`consent_evidence`), department revoke, unique active link index, merge pointers.
5. Startup guards (DB passwords, `*-change-me`, demo-only providers and mock rows behind profiles).
6. Front end: confirm on Approve/Reject, relabel counts, citizen 360 server-side filters, UNKNOWN health state.
7. CI: build `departments/`, run the end-to-end IT, python test.
