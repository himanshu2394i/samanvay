Feasibility and viability

Feasible now

  • Core already runs: Java 21 / Boot 4 / Postgres / three published journeys.
  • Heterogeneous mocks are the proof (SOAP, REST, JDBC, SFTP).
  • PS constraint met: no replacement of existing department systems.
  • Onboarding a journey is catalog + connectors + BPMN, not a rewrite. Farmer subsidy proves this — zero new Java, ready skin at /farmer/.
  • Demo is fully offline — venue network is not a dependency.

Challenges / risks

  • Live DigiLocker / Aadhaar needs a MeitY partner account (not on this laptop).
  • Real department APIs need MoU / NIC / department credentials.
  • Keycloak brokering and BPMN depth are fiddly in production. Demo identity is AUTH STUBBED.
  • Probabilistic identity merge is unsafe if auto-applied.
  • Officer queues and SLA if a source stays down — not a gateway retry loop.

How we overcome them

  • Sandbox labelled as sandbox; issuer mocks stand in for systems of record.
  • WorkflowEngine port: BPMN today, YAML DAG fallback in ~2 days.
  • CHECK + service + RBAC: a probabilistic match never becomes an active link.
  • Degraded mode + officer retry (mark a department unavailable in demo, restore, retry).
  • Recorded backup walkthrough if live demo fails.
