USER FLOW: HOW SAMANVAY ADDRESSES THE PROBLEM

Not a new portal and not a data lake. Certificates stay at the issuer. Samanvay stores only links, consent, pointers, workflow, tracking, and a hash-chained audit trail.

STAGE 1 · APPLY & LINK

CITIZENFacts already issued by the department of record — income, caste, 7/12, marks, NOC
▼
ANY EXISTING PORTALScholarship · Licence / NOC · Farmer subsidy. Three callers, one core.
▼
IDENTITY LINKINGMap IDs across departments. Probabilistic matches never auto-merge.

DigiLocker may carry issued copies. It is not login and not Samanvay’s consent store.

STAGE 2 · CONSENT

CITIZEN GIVES CONSENTPurpose, requester, and categories only — never a blanket dump
▼
CONSENT ARTIFACTOwned by the consent module. Revoke anytime; version increments.
▼
JOURNEY STARTSBPMN fetches only what this scheme needs

A scholarship grant cannot later pull a fire NOC.

STAGE 3 · CONTROL PLANE DECIDES

ACCESS AUTHORITYIdentity + consent + registry, together
1. Identity: active department link?
2. Consent: covers requester, category, purpose?
3. Registry: pointer exists? (what lives where — never the payload)
ANY NO → DENYReason written on the audit chain
ALL YES → SIGNED GRANT60-second TTL, single-use nonce. No fetch without it.

STAGE 4 · DATA PLANE MOVES

CONNECTOR RUNTIMEVerify signature, expiry, unused nonce
▼
PROTOCOL ADAPTERSREST · SOAP · SFTP · JDBC → canonical model, in memory
▼
LIVE FETCH FROM SYSTEM OF RECORDAaple Sarkar · Mahabhulekh · Education · Fire · MPCB · MahaDBT
IF SOURCE DOWNStatus = PARTIALLY_VERIFIED. Retry + officer queue. Citizen file is not restarted.
IF UPField used in workflow only. Payload is never persisted.

STAGE 5 · TRACK & PROVE

ONE TRACKING IDOne reference across every department, e.g. Req-12345
▼
OFFICER DESKSee which issuer answered. Retry a downed dept without a new file.
▼
HASH-CHAINED AUDITWho asked, when, where, grant id. Never the certificate.
▼
REVOKE → NEXT FETCH DENIEDWithin 60s. Nothing to purge — it was never stored.
